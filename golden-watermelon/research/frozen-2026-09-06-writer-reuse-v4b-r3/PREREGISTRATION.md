# White 저장 연결 재사용 보정 v4b-r3

2026-09-06 운영자 요청. v4b-r2의 종목·진입·손절·규모·기간·스키마는 유지한다.
NFL 정규시즌·플레이오프·Super Bowl을 포함한 다섯 종목의 기존 식별 계약을 유지한다.
데이터를 삭제·이전·병합하거나 실패 cycle을 성공으로 바꾸지 않는다.

기존 저장 경로는 영수증·호가를 저장할 때마다 SQLite 연결을 열고 닫았다.
외장 디스크에서 마지막 WAL 연결 종료에 따른 반복 checkpoint를 피하도록 한 invocation의
직렬화된 writer를 재사용한다. 각 최상위 저장 작업은 synchronous=FULL로 commit하며,
실패 작업은 rollback한다. worker의 동시 접근은 잠금으로 직렬화하고 완료/실패 후 연결을 닫는다.
기존 42초 network / 50초 cycle 예산과 미완결 실패 판정은 완화하지 않는다.
정기 cycle의 일일 전체 quick_check도 분리한다. 매 cycle 스키마/계약 읽기 검사는 유지하고
full_check_due를 기록한다. 전체 무결성 검사는 별도 health 또는 검증된 사본에서 수행해야 하며,
가벼운 검사만 수행하고 전체 DB 무결성을 통과했다고 표시하지 않는다.
저장/health 뒤 성공 게시 직전에도 시간 예산을 재검사한다. 이미 50초를 넘은 결과를
잔여시간0의 SUCCESS로 게시하지 않는다. OS/디스크의 blocking commit 시간을 강제 종료로
숨기지 않으므로 이 검사 역시 1분 이내 완료의 절대 보장은 아니다.

오프라인 검증: 연결 재사용, 독립 읽기로 commit 확인, rollback, 동시 worker 쓰기,
명시적 close 후 재열기, 기존 수집/해결/스키마 계약 테스트.
로컬 통과는 외장 디스크의 1분 미만 실행 증거가 아니다. 배포 후 build 전체 시간,
family별 cursor와 최신 DB를 재검증해야 한다. 기존 원자료와 새 source/config를 구분한다.
