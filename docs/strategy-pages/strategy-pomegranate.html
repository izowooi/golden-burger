🔴 Market Observatory

돈을 버는 규칙을 먼저 고르지 않는다. Polymarket의 전체 non-closed universe와 가격·거래량·유동성·시계·outcome·표본 CLOB book·resolution 경로를 point-in-time으로 축적해, 나중에 어떤 전략과 parameter가 실제로 살아남는지 검정하는 계좌 없는 관측소다.

RESEARCH ONLY · LIVE/ORDER HARD BLOCK

기존 전략과 무엇이 다른가

전략 gate가 없다

0.90 이상, 72시간 이내, 유동성 $10k 같은 조건은 모두 미래 feature다. 수집 단계에서 시장을 잘라내지 않는다.

복수 outcome도 원형 보존

YES/NO만 남기지 않고 outcome index, label, token ID, reference price를 variable-length row로 저장한다.

실행 가능성도 표본화

condition hash 기반 deterministic rotation으로 public CLOB book을 수집하고 bucket·cyclic offset·reason·coverage를 함께 남긴다.

종료일과 해결을 구분

endDate, closed, one-hot outcome, redeemable을 별도 사실로 기록한다. fill/P&L을 만들지 않는다.

Public trade tape의 정확한 범위

WebSocket tick 전수가 아니라 15분 polling 관측이다. 공개 Data API를 takerOnly=true로 읽으므로 maker-side participant archive나 complete historical tape라고 주장하지 않는다. 첫 baseline은 현재보다 24시간 전에서 시작하되 한 cycle에 최대 3,600초만 전진한다. 실제 HTTP 시도 64회, 전체 logical/sub-window node 32개, worker runtime 120초 중 하나라도 소진되면 BUDGET_EXHAUSTED와 possible_gap=1을 남기고 watermark를 전진시키지 않는다. 다음 cycle은 같은 안전한 경계에서 다시 수집한다.

왜 compact하지 않는가

research-full-v1은 수집된 bundle을 thinning하지 않는 계약이다. upstream API와 15분 polling 자체가 모든 tick을 포착한다는 뜻은 아니다. 다만 수집에 성공한 bundle에는 기존 compact-v1의 hot/cold rollup, 24시간 membership checkpoint, row retention delete를 적용하지 않는다. 대신 활성 trades_sim.db를 UTC 일 경계에서 trades_sim_YYYYMMDD.db로 회전한다. 완전한 WAL checkpoint와 idle reader를 검출하는 WAL→DELETE ownership barrier를 통과한 shard만 닫고, 검증된 backup 뒤 완결 shard 단위로만 보존한다. 압축 BLOB은 byte encoding을 줄일 뿐 관측치를 합치거나 삭제하지 않는다.

이 자료로 전략을 고를 때

완전 sweep만 사용하고, 같은 event는 같은 split에 두며, 미래 closed/outcome으로 과거 universe를 거르지 않는다. Gamma reference price와 CLOB quote를 구분하고, CLOB rotation의 selection bias를 보고한다. forward return·MFE/MAE·barrier label은 raw DB를 수정하지 않는 versioned derived artifact로 만든다. 가장 좋아 보이는 threshold를 같은 기간에 다시 평가해 “전략”이라고 부르지 않는다.
