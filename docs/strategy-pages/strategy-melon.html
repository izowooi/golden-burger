4. 진입 / 청산

진입 = 표준 이진 YES (negRisk false), YES-only
     + 직전 저장 YES < 0.85 AND 현재 YES ∈ [0.85, 0.93]   ← 최초 상향 교차만
     + 두 snapshot 간격 0분 초과 15분 이하
     + 해결까지 (0h, 72h]
     + 24h 거래량 ≥ min_volume_24h        ← A/B/C 처치축
     + 유동성 ≥ max($20,000, 주문액/0.001)
     + spread ≤ 0.02, ask depth ≥ 주문 수량 × 1.2

청산 = YES ≥ 0.97 이고 fresh bid ≥ 0.97   → take_profit
     또는 YES ≤ 0.78                      → absolute_stop
     trailing stop 없음, time exit 없음

5. 배리어로는 edge가 생기지 않는다

밴드 중앙 0.89 기준
목표 0.97 = +9.0%  |  손절 0.78 = −12.4%
손익분기 승률 = 12.4 / (9.0 + 12.4) = 58.0%
martingale 도달확률 = (0.89 − 0.78) / (0.97 − 0.78) = 57.9%

두 값이 같다. quince가 9개 배리어 조합을 갭 반영 재생으로 검정해 보정 p=0.27로 확인한 것과 같은 결론이다. 따라서 edge는 진입 선별에서만 올 수 있다.

7. A/B/C 설계

단조성이 판정이다. 순서가 단조가 아니면 거래량은 선별 축이 아니며, 그 자체가 결론이다. 팔당 최악 손실 약 −$70, 3팔 총 최악 약 −$210.

거절된 후보도 자산이다. skipped_markets에 거절 사유와 당시 volume·liquidity·잔여시간이 남으므로, 30일 뒤 실행하지 않은 threshold의 반사실을 오프라인으로 계산할 수 있다. live A/B는 세 점만 재지만 로그는 연속 곡선을 준다.

8. 이 전략이 실패하는 경우

  1. 캘리브레이션이 맞다. 가장 유력하다. 0.85~0.93이 정확히 가격대로 해결되면 EV는 0이고 비용만큼 음수다.
  2. 점프 위험이 그대로다. 60%/30분 문제가 시장 구조라면 금액이 작아 파산은 없지만 edge도 없다.
  3. 신호가 희소하다. $150,000 gate에서 후보가 0에 수렴하면 C팔 판정이 불가능하다.
  4. 거래량이 선별 축이 아니다. 세 팔이 구분되지 않으면 처치 자체가 무효다.

9. 알려진 한계

cherry 진단은 daily-rsync catalog에 없는 작업트리 사본 하나에 근거한다. verify·local_sha256 증빙이 없고 polybot-yellow· polybot-orange의 DB는 동기화되지 않았다. 운영자가 기억하는 "월간 10%" 구간은 이 사본에 없다(4월 −0.46%, 5월 −9.93%). melon의 설계 근거로는 쓰되 cherry의 최종 판정으로 인용하지 않는다.
