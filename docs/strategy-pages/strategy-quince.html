golden-quince — Spread Harvest

"시장을 이기려 하지 않는다. 스프레드를 내는 쪽이 아니라 받는 쪽에 선다." — 방향성 예측을 포기하고 실행 측면(maker/taker) 하나만을 수익원으로 삼는 전략.

유형 실행 비용상태 구현 완료 · 시작 evidence 없음처치축 BUY execution_mode기본 주문 $5신호 24h 고정

핵심 아이디어

가격 = 실현 확률  (실측: 99개 셀 중 BH 통과 0개)
   ⇒ 매수 후 보유의 기대값은 비용 전 0

   ⇒ 양수 EV의 출처는 하나뿐: 거래비용의 부호를 바꾸는 것

처치(BUY만):
  A passive = floor(midpoint)   # 매수호가 합류
  B nearest = round(midpoint)   # 기존 대조
  C cross   = ceil(midpoint)    # BUY 크로스

SELL = nearest                  # A/B/C 모두 동일, 처치 아님

왜 이 전략인가 — 다른 모든 것이 기각됐다

2026-07-28~29에 5개 전략(cherry·lime·fig·mango·date)을 실측 검증하고 4개를 폐쇄했다. 가설은 전부 달랐지만 결과는 같았다.

검정한 것결과
확률 예측 edge없음. 99개 셀 중 Benjamini-Hochberg q=0.05 통과 0개. 최대 |z|=2.47인데 필요 p ≤ 0.0005
경로 구조 (평균회귀)실재하나 작다. rho=−0.0901, t=−26.2로 매우 유의하지만 되돌림이 7.9 bps에 불과
청산 규칙 edge없음. 통합 785건 +0.44pp, p=0.74. 초판의 "+$633 이득"은 체결기록 결손 artifact였고 철회됨
실행 측면진입 leg에서 ~73 bps 차이 — 유일하게 남은 것

실측 왕복 비용은 실행 경로에 따라 부호가 뒤집힌다 ($5 주문 2,139 왕복):

실행 경로비중왕복 비용
buy MAKER → sell MAKER41.5%−31.1 bps (버는 쪽)
buy MAKER → sell TAKER18.2%−33.4 bps
buy TAKER → sell MAKER23.0%+32.8 bps
buy TAKER → sell TAKER13.8%+72.5 bps

다만 처치는 진입(BUY) leg에만 적용하므로(아래 "진입·청산 규칙" 참조), 우리가 실제로 움직이는 양은 매수 leg의 차이다:

진입 leg비용95% CI
MAKER−16.8 bps[−19.1, −14.3]
TAKER+56.7 bps[+54.3, +59.0] (97.5%가 지불)

차이가 약 73 bps이고, 결정적으로 분산이 매우 작다(CI 폭 ±2 bps). 이 성질이 아래 A/B/C의 검정력을 결정한다.

메커니즘 — 기존 14개 봇은 이 축이 무작위였다

rounded = round(round(price / tick_size) * tick_size, 2)   # 가장 가까운 틱

호가가 0.79/0.80이면 midpoint는 0.795다. 이것이 0.80으로 반올림되면 매도호가를 리프트해서 taker가 되고, 0.79로 내려가면 매수호가에 합류해 maker가 된다. 어느 쪽이 될지는 midpoint 셋째 자리에 달려 있다 — 사실상 무작위다.

golden-date 실거래에서 이 축을 준무작위 자연실험으로 측정한 결과:

반올림 방향n체결률
UP (매도호가 리프트 = taker)49391.1%
DOWN (매수호가 합류 = maker)48739.4%

다만 "무작위"는 과장이다. 결정 midpoint의 52~68%가 정확히 반 틱 위에 놓이는데, 그 지점에서 round()는 가격에 대해 결정적이다. 따라서 반올림 방향은 가격 수준의 함수이고, 가격 수준은 결과와 상관이 있다 — 밴드 통제 시 부호가 뒤집힌 것도 이 교란 때문일 수 있다. 정확히는 "가격 수준 교란이 있는 준무작위 배정"이며, 그래서 실제 MAKER 비중은 가정하지 않고 팔별로 실측 기록한다.

quince는 이 BUY 축을 execution_mode로 설정에 고정한다. SELL은 mode와 무관하게 항상 nearest다.

⚠ 경쟁 가설 — 아직 기각되지 않았다

"패시브가 얻는 1틱 할인은 역선택으로 상쇄된다." 패시브 주문은 가격이 나에게 내려왔을 때 체결되고, 그것은 계속 내려갈 수 있다는 뜻이다.

golden-date에서 진입 밴드를 통제해 종결 ROI를 비교하면 부호가 밴드마다 뒤집힌다(−3.80 / −12.01 / +6.37 / +2.64 pp, n=30~64). 역선택은 현재 DB로 측정 불가능하다 — 거래에 가장 가까운 snapshot이 평균 135분 떨어져 있다.

그래서 이 전략은 "확신"이 아니라 사전 등록된 실험이다.

진입 · 청산 규칙

고정된 Crown Momentum signal contract를 의도적으로 그대로 사용한다. 신호가 아니라 BUY 실행이 처치이므로, 24시간 horizon을 포함한 신호는 A/B/C 전 팔에서 동일해야 한다.

#진입 조건 (모두 충족)
1표준 이진 시장 ([Yes, No], price/token 각 2개, negRisk is False 명시)
2YES-only
3직전 persisted YES < 0.90 AND 현재 YES ∈ [0.90, 0.94] — 최초 상향 교차만
4lineage: 현재 snapshot은 이번 sweep의 양의 ID, 직전과 0 < gap ≤ 15분
5시계: 비스포츠·경기 전 (0h, 24h], 경기 중은 kickoff 후 360분까지
6event_id 필수, event당 동시 1개
7주문 직전 fresh midpoint가 밴드 안, best ask ≤ 0.94, spread ≤ 0.02, depth 1.2배, 최소 5.1주
우선순위청산 조건exit_reason
1fresh YES ≥ 0.98 AND 실행가능 bid ≥ 0.98take_profit
2fresh YES ≤ 0.85absolute_stop

처치는 진입(BUY)에만 적용한다. 청산은 전 팔에서 nearest로 동일하다. passive를 SELL에 적용하면 ceil(mid)가 되어 최우선 매수호가보다 위에 주문이 걸린다. 익절은 그래도 괜찮지만 absolute_stop은 치명적이다 — 시장가보다 비싸게 내놓는 손절은 체결되지 않고, 체결되지 않는 손절은 손절이 아니다. 비대칭이 실재한다: 진입에서 미체결은 무해하지만, 손절에서 미체결은 손실 포지션을 그대로 안고 가는 것이다. 부수 효과로 청산이 전 팔에서 동일해져 진입 축의 대비가 더 깨끗해진다.

trailing stop과 time exit은 없다. 청산 규칙에 edge가 없음이 785건에서 확인됐고(+0.44pp, p=0.74), time_exit의 SELL leg는 TAKER 비중이 59.4%(+16.2 bps)라 패시브 원칙과 정면 충돌한다. 또 max_price를 매수가로 초기화하는 트레일링은 명목 손절을 도달 불가능하게 만든다(cherry·date·grape에서 확인, 실제 발동 중앙값 −14.2% / −16.8%).

A/B/C 3팔 설계 (사전 등록)

처치는 실행 측면 하나다. 신호·금액·캡·청산은 전 팔에서 동일하다.

팔Jenkins job = --jobDBBUY mode역할
Apolybot-quince-passivedata/polybot-quince-passive/trades.dbpassive처치군 — BUY 크로스 안 함
Bpolybot-quince-nearestdata/polybot-quince-nearest/trades.dbnearest대조군 — 기존 방식
Cpolybot-quince-crossdata/polybot-quince-cross/trades.dbcross비용 상한 — BUY 크로스

격리 계약: A/B/C는 서로 다른 wallet/account, Jenkins credentials, job, --job, DB를 쓴다. 세 job의 cadence는 모두 H/5 * * * *이고 concurrent build는 끈다. Git commit, $5 주문, 24시간 signal horizon, threshold, risk, sports, lifecycle은 고정한다. SELL은 모든 팔에서 nearest다.

Private key와 funder는 Jenkins Credentials Binding으로만 주입하고 값은 shell·문서·로그에 쓰지 않는다. secret을 참조하기 전부터 set +x를 적용한다.

# A — wallet A / Jenkins job polybot-quince-passive / H/5 * * * *
set +x
export POLYBOT_EXECUTION_MODE=passive POLYBOT_BUY_AMOUNT=5 POLYBOT_ENTRY_HOURS_MAX=24
uv run polybot run --live --job polybot-quince-passive

# B — wallet B / Jenkins job polybot-quince-nearest / H/5 * * * *
set +x
export POLYBOT_EXECUTION_MODE=nearest POLYBOT_BUY_AMOUNT=5 POLYBOT_ENTRY_HOURS_MAX=24
uv run polybot run --live --job polybot-quince-nearest

# C — wallet C / Jenkins job polybot-quince-cross / H/5 * * * *
set +x
export POLYBOT_EXECUTION_MODE=cross POLYBOT_BUY_AMOUNT=5 POLYBOT_ENTRY_HOURS_MAX=24
uv run polybot run --live --job polybot-quince-cross

왜 대조군이 둘인가. B만 있으면 "A가 B보다 낫다"를 관측해도 실행 때문인지 우연인지 모른다. C가 있으면 예측된 순서가 생긴다:

MAKER 비중:  A  >  B  >  C
진입 비용:   A  <  B  <  C     (bps, 결정 midpoint 대비)
체결률:      A  <  B  <  C

이 부등식이 깨지면 우리의 비용 모형이 틀린 것이고, 그 자체가 정보다. 단일 대조군으로는 얻을 수 없는 falsifiability다.

선택적 4번째 팔 D는 별도 wallet/job/DB에서 passive + POLYBOT_BUY_AMOUNT=10으로 크기 효과만 분리한다. A·B·C가 우선이다.

1차 종점은 순손익이 아니라 실행 지표다. 순손익은 해결 결과가 지배한다 — p≈0.92에서 YES는 +8.7%, NO는 −100%라 건당 표준편차가 약 2,900 bps다. 여기서 ~73 bps를 80% 검정력으로 탐지하려면 팔당 수만 건이 필요하다. 30일 25건으로 "A ≤ B"를 판정하면 동전던지기이고, 판정 불가능한 기준을 사전 등록하는 것은 golden-date의 실패를 숫자만 적어서 반복하는 것이다.

1차 종점 (30~50 체결이면 판정 가능)예측
MAKER 체결 비중 (order_fills.liquidity_role)A > B > C
실효 체결가 − 결정 midpoint (bps, 진입 leg)A < B < C (A는 음수여야)
체결률A < B < C
시점조건결정
상시경제손익(확정+해결추정) ≤ −$40자동 중단
30일A의 CONFIRMED 진입 체결 < 30건판정 불가 → 진입 조건 완화 후 재시작
30일A의 MAKER 비중이 B보다 유의하게 높지 않음구현 실패 — 처치가 작동하지 않았다
30일A의 진입 비용(bps)이 B보다 낮지 않음가설 기각
30일위 둘 성립 AND 역선택 표류 < 진입 할인계속, 선택적 D $10 검토

순손익 A vs B는 표본 부족으로 판정 불가이며 부호만 기록한다. 역선택은 패시브 체결 후 15/60분 midpoint 표류로 잰다 — 가격 표류라 해결 결과보다 분산이 훨씬 작아 낮은 n에서도 유의미하다.

"승률"과 "순손익"은 1차 판정 기준이 아니다. 승률은 진입 밴드가 결정하며 처치와 무관하고, 순손익은 이 표본 크기에서 처치 효과를 담을 수 없다. 재는 것은 같은 신호에 대한 순 진입 실행 비용 차이다.

이 전략이 실패하는 경우

  • 역선택이 스프레드보다 크다. 가장 유력한 실패 모드. → A vs B가 이것을 잰다.
  • 체결이 안 된다. 패시브 체결률 39%대, 0.90~0.95 밴드의 $5 주문 체결률 36.2%. 자금 거절까지 포함하면 신호→포지션 전환율 ~25%.
  • 미체결분이 유령이 된다. 미체결 $5 BUY의 36.4%가 INVALID로 전환되어 max_positions를 잠식한다. 패시브는 미체결이 많으므로 이 위험이 더 크다.
  • 신호가 너무 희소하다. 선행 관측에서는 약 15,500개를 훑어 후보 2건만 나왔다. 진입이 0에 수렴하면 A/B/C가 성립하지 않는다.
  • dust 잔류. 체결 $5 BUY의 0.3~0.9%가 5주 미만으로 남아 영구 매도 불가.
  • 수수료가 실제로 부과된다. 기록된 fill의 수수료는 전부 0/NULL이지만 Gamma 메타데이터는 94% 시장에 fee_rate 0.04~0.07을 붙이고 있다. 이 불일치는 미해결이다.

알려진 한계

  • 역선택 미측정이 가장 큰 미지수다. market_snapshots에 bid/ask를 함께 적재하므로 30일 뒤에는 직접 측정이 가능해진다.
  • 캘리브레이션 연구는 1주다. favorite 밴드에서 3~8pp의 진짜 edge는 이 표본 크기로는 보이지 않는다(MDE 8~9pp). "edge가 없다"가 아니라 "edge를 보지 못했다"이다.
  • 성과는 order_fills.status='CONFIRMED'로만 확정한다. midpoint 기반 P&L 금지.
  • 패시브는 체결률을 절반 이하로 떨어뜨린다. 부작용이 아니라 설계의 일부이며 표본 축적 속도와의 트레이드오프다.
