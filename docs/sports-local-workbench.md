# 로컬 경기 웹앱

Mac에서 **Daily Rsync**를 실행하고 상단의 **경기 보기**를 누른다.
주소는 `http://127.0.0.1:8765/sports`다. 외부 웹에 배포하지 않는다.

터미널에서 실행하려면 다음 명령을 사용한다.

```bash
cd daily-rsync
uv sync --frozen
uv run daily-rsync serve --no-open
```

## 자료를 추가하는 순서

1. **수동 동기화** 화면에서 원하는 Jenkins job의 계획과 용량을 확인하고 DB를 가져온다.
2. **경기 보기 → 로컬 DB에서 경기 목록 만들기**를 펼친다.
3. 로컬 자료와 UTC 시작·종료 시각을 선택한다. 종료 시각은 포함하지 않으며 한 번에 최대
   31일을 읽는다. **선택한 자료로 목록 만들기**를 누른다.
4. 종목과 수집 자료를 고르고 팀 이름으로 경기를 찾는다. 관측 시각은 KST로 표시한다.

경기 화면을 열거나 필터를 바꾸는 것만으로 서버 DB를 동기화하지 않는다. 목록 만들기도
이미 받은 로컬 snapshot만 검사한다. 원본 SHA-256과 SQLite 무결성을 확인한 새 목록이
완성돼야 현재 목록을 교체한다. 동기화 도중 원본이 바뀌면 게시하지 않는다.

## 차트와 손익 계산

축구는 HOME/DRAW/AWAY의 직접 YES·NO 6개를 표시한다. MLB·NFL·NBA·NHL의 표준
두 팀 moneyline은 실제 2개 token을 표시한다. 없는 NO나 무승부를 합성하지 않는다.
기록이 없는 종목은 0경기로 남으며, 일부 결과만 수집됐으면 기대 개수와 실제 개수를
함께 표시한다. 같은 경기의 서로 다른 job/cohort를 합쳐 연결하지 않는다.

차트의 `$5 매수 평균가`는 각 시점의 ask 잔량을 $5만큼 걸은 가격이다. 차트의 bid 평균가는
**그 시점에 새로 $5를 샀을 때의 수량**을 파는 값이다. 과거 A에서 보유한 수량을 파는
값은 아래 계산기를 사용한다. 90초 이상 관측 공백과 실패 구간은 선으로 연결하지 않는다.

`정규화 가격`을 고르면 같은 관측 묶음의 결과 가격을 합계 S로 나눈 값을 본다.
아래 S 차트는 최우선 ask·mid·bid 합, 또는 각 결과 **같은 5주**를 사고파는 평균가의
합을 표시한다. 1에서의 이탈과 스프레드를 함께 확인할 수 있다. 축구 분모는 YES 3개이며,
NO 선은 `1−정규화 YES`의 이론값이다. 실제 NO 매수·매도 계산에는 직접 호가만 사용한다.
이 값은 검증된 실제 승률이 아니다. 원본 수신 시각이 검증된 자료와 DB 기록 시각만 남은
과거 자료를 구분하며, 수수료·주문 가능 상태가 없는 관측은 매매 근거로 승격하지 않는다.
계산 정의와 제한은 [S와 정규화 가격](sports-price-normalization.md)을 참고한다.

고정된 S 전수 연구 결과는 `/sports/study`의 별도 탐색기에서 종목·경기·출처·cohort·
기록 간격으로 나누어 볼 수 있다. 과거 1분·5분 자료와 BBO 진단을 구별하며, S 분모가
불완전한 경기도 목록에서 숨기지 않는다. 이 화면은 원래 호가의 A/B 현금 계산 화면과 별개다.
연구 결과 디렉터리를 입력해 로컬 HTML을 생성하면 해당 고정 파일만 읽어 제공한다.

```bash
python3 tools/sports_s_viewer.py --analysis-dir /path/to/frozen-analysis \
  --output daily-rsync/data/sports-view/research.html
```

이 명령은 저장소 루트에서 실행한다. DB 동기화·가격/수익 재계산·외부 네트워크 요청은 없다.
생성된 HTML과 연구 자료는 `data/` 또는 local-only 경로에 보관하며 source package에 넣지 않는다.

계산기에서 결과 token, 금액, A 매수 관측, B 매도 관측을 선택한다. A의 전체 ask에서 산
실제 가상 수량을 고정하고, B의 전체 bid에서 그 수량을 판다. 매도 수량은 0.01주 단위로
내림하고 미매도 잔량은 별도로 표시한다. 전량을 채울 잔량이 없거나 시장이 닫혔거나
식별·실행 근거가 부족하면 계산을 거부한다. 시장의 주문 가능 상태 자체가 기록되지 않은
과거 자료는 호가 계산이라는 제한을 표시한다.

수수료는 양쪽 시점에 기록된 명시적 면제 또는 지원되는 fee schedule을 사용한다.
한쪽이라도 근거가 없으면 순손익은 **확인 불가**다. 사용자가 rate를 직접 넣으면
`q × p × (1−p) × rate`를 각 호가 체결 구간별로 계산한 **가정 손익**으로 표시한다.
현금 수수료 방식(v2)을 가정하며, 과거 share 수수료 방식의 실거래 대사를 대신하지 않는다.

이 계산은 선택한 A에서 B까지 보유하는 표시 호가 반사실이다. 중간 TP·SL, queue,
실제 체결, 주문 지연을 재생하지 않는다. 실제 전략 손익은 `sports-trade-report` 스킬로
CONFIRMED fill·수수료·정산 근거를 따로 대사한다.

## 보관과 지원 범위

Peach·Plum의 legacy snapshot 및 `full-sports-raw-v1`, Coconut의 새
`sports-price-recorder-1m-v1`을 지원한다. 통합 수집기의 UTC 일별 DB는 같은 runtime과
config/source cohort끼리 연결하며, 각 원본 SHA와 선택된 부모 shard의 인계 상태를 검증한다.
같은 날짜의 중복 snapshot과 과거 Coconut v7은 연결하지 않는다. DB 경로를 임의 입력하는 대신 Daily Rsync
catalog에서 확인된 자료만 선택한다. 결과 캐시는 ignored `daily-rsync/data/sports-view/`에
원본과 분리돼 저장된다. 원본 DB·로그·cohort는 수정하거나 삭제하지 않는다.

목록을 새로 만들면 이전에 열어 둔 계산의 관측 번호가 달라질 수 있으므로, 서버는
화면 버전이 일치하지 않는 계산을 거부하고 경기를 다시 선택하도록 안내한다.
