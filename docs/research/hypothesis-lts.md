# 가설: 후반 임계 안정성 (LTS — Late Threshold Stability) — 정의·사전 등록·검증

- 연구자 요청 2026-10-10 (`hypothesis:lts`): "경기가 일정 진행 시점을 지나고 승리 확률이 임계값을 넘으면, 다시 그 아래로
  떨어지거나 끝내 역전되는 경우가 얼마나 드문가?" 예: 80% 진행 뒤 0.60 이상인 팀을 사서, 또는 60% 진행 뒤 0.61 이상인 팀을 사서
  끝까지 보유. "90% 면 안전하다"를 전제하지 않고, 종목·시점·임계값 중 **통계적으로 유의하면서 수익이 나는** 칸을 찾는다.
- 체결은 **수수료 없는 지정가(maker)만**: 매수호가보다 한 틱 아래에 걸고 기다린다(taker 금지, 비싸게 사지 않음). 연구자 판단:
  taker 수수료는 YES+NO 를 1.0 위로 밀어 가설과 모순된다.
- 연구자가 준 참고 문헌(NBA·NFL 에서 처음 95% 를 넘은 팀이 지는 사례): https://academ.us/article/2601.18774/ ,
  https://www.sciencedirect.com/science/article/pii/S2214635026001218 — **두 곳 모두 2026-10-10 접속이 403 으로 막혀 본문을 읽지
  못했다.** 연구자가 제공한 참고 자료로만 적고, 내용(수치·결론)은 인용하지 않는다.
- **이 문서의 손익은 모두 과거 데이터 재생(백테스트)이며 실현 손익이 아니다.**

## 1. 정의

| 용어 | 정의 |
|---|---|
| 선두(leader) | 무승부 없는 종목(NBA·NHL·NFL·MLB): moneyline 두 팀 토큰 중 가격이 높은 쪽. 축구(3결과): 홈·원정 **팀 승리 Yes** 토큰 중 높은 쪽(무승부 Yes 는 사지 않음, **무승부는 손실**). 두 토큰 가격 차 ≥ 0.005 |
| 진행 시점 T | **예정 시작 시각 이후 벽시계 분**. 과거 데이터에는 경기 시계·점수(`game_states`, 2026-09-30~ 실시간만)가 없으므로 이닝·아웃·남은 시간·점수는 쓰지 않는다. 종료 시각(`ended_at`)은 미래 정보라 시계로 쓰지 않는다. 백테스트·평가기·실거래 모두 같은 시계 |
| 진행률 % | T ÷ 종목별 중앙 경기 길이(예정 시작→`ended_at`, 벽시계). 연구자의 "60·70·80·90% 진행"을 분으로 바꾸는 데만 쓴다(아래 표) |
| 임계값 Y | 0.60·0.65·0.70·0.75·0.80·0.85·0.90·0.95·0.97·0.99 |
| 신호(signal) | 경기당 1회: 벽시계 분 ≥ T 인 첫 분 중 선두 가격이 진입 밴드 [Y, min(Y + δ, 0.995)] 안에 있는 분(두 팀 가격 모두 120초 이내 신선). δ = 0.03 (사전 고정). 그 전에 밴드 위에 있다가 내려와 밴드에 들어온 경우도 신호다(연구자 문장 "넘으면"을 상태로 해석; 교차 여부는 따로 고르지 않음) |
| 재이탈(re-break) | 신호 뒤 경기 끝까지 선두 가격이 한 번이라도 Y 아래로 떨어짐 |
| 최대 낙폭(MDD) | 신호 가격 − 신호 뒤 최저 가격(가격 포인트). 중앙값·p90, 최종 승자만의 값도 따로 |
| 역전(reversal) | 선두가 최종적으로 짐(축구는 무승부 포함) |

## 2. 체결 모델 (핵심)

과거 데이터는 1분 가격(중간가에 가까운 canonical bar)뿐이고 호가창이 없다. 그래서:

- **지정가 위치**: 신호 분의 선두 가격 p 로 합성 매수호가 bid = p − hs (hs = 반 스프레드 0.005), 지정가 L = bid − tick.
  tick 은 결정론 규칙: 가격이 [0.04, 0.96] 안이면 0.01, 밖이면 0.001(Polymarket 극단 가격 tick). `execution/maker.entry_price`
  (`entry_price_rule: below`)와 같은 반올림. hs 0.005 는 2026-09-30~10-10 저장 호가(경기 중, 거래 리그) 실측과 맞다:
  종목 × 가격 구간(0.55–0.95)별 스프레드 중앙값 0.01(0.95+ 는 0.003–0.007), p75 0.01(NBA 0.02), p90 0.01–0.03.
- **체결은 엄격한 관통(trade-through)만**: 주문을 낸 분 **이후** 바(ts > 주문 시각) 중 가격이 L 보다 **엄격히 낮은** 바가 나오면
  그 바에서 전량 체결, 가격은 L(지정가), **수수료 0**(maker; sports_fees 는 taker-only). 대기열 위치는 모른다고 보고 "같은 가격"은
  체결로 치지 않는다. 신호마다 무조건 bid − tick 에 체결시키는 계산은 하지 않는다(가공물).
- **같은 분에는 체결이 취소보다 먼저**: 엔진(`engine/tick.maintain_maker`)은 매 분 체결을 먼저 반영하고 그다음 취소 조건을 본다.
  실제로도 관통은 1분 사이에 일어나 우리가 반응하기 전에 체결된다.
- **보유**: 정산까지(익절·손절 없음). 경기 직후 패자 가격이 0.01 로 무너지는 순간의 체결도 실제 체결로 남긴다(별도 집계).
- **비교 기준(taker)**: 같은 신호를 합성 매도호가 p + hs 로 즉시 사고, 수수료 = 주식 수 × 0.05 × p × (1 − p)(현재 sports_fees_v3).
- **역선택 보고**: 체결률을 최종 결과별로 나눠 보고한다(P(체결 | 선두 승), P(체결 | 선두 패)). 후반 지정가는 선두가 무너질 때
  주로 체결된다는 연구자 우려를 직접 잰다.
- **두 분모**: 체결당 ROI(Σ손익 / Σ체결 원가)와 신호당 기대 손익(Σ손익 / 신호 수, intention-to-treat).

### 취소 규칙 (사전 고정)

- 지정가는 처음 건 가격에 **고정**한다(위로 따라가지 않음 — 재호가 없음: `maker_reprice_ticks` 매우 큼, TTL = 대기 시간).
- **경기당 1회 시도**: 미체결로 취소된 경기에는 다시 들어가지 않는다.
- 대기 시간 W ∈ {5분, 30분, 끝까지}: 주문 후 W 가 지나면 취소. "끝까지" = 경기 종료(시장 정산·거래 중지) 또는 예정 시작 + 종목 최대
  시간(NBA·NHL 5h, NFL·MLB 6h, 축구 3h).
- 가격 하한 c = 0.05: 선두 가격이 Y − c 아래면 취소. **같은 분 체결이 먼저이므로 L 보다 낮은 하한은 체결을 막지 못한다**
  (그 바는 이미 L 아래라 체결된다). L 보다 높은 하한은 완만한 하락에서 체결 전에 주문을 거둬 "갭으로 뚫린 경우"(가장 나쁜 체결)만
  남긴다. 그래서 하한은 안전장치로만 두고(사실상 비구속), 실제 취소 축은 대기 시간 W 다.

## 3. 사전 등록 (grid 실행 전에 고정, 결과를 본 뒤 바꾸지 않음)

- 데이터: 운영 `core.db` 를 `VACUUM INTO` 로 만든 사본(2026-10-10 19:48 KST, Mac mini `/Volumes/t7/polylab/scratch/lts-1010`,
  작업 후 삭제). 저장 호가 shard 2026-09·10 사본(스프레드 실측·엔진 재생용).
- 표본: 2026-10-10 까지 끝나고 정산된 경기. NBA 2024-04~, NHL 2024-10~, NFL 2024-08~, MLB 2026-03~(**한 시즌뿐**), 축구 2026-02~
  (**8개월**, 거래 리그 epl·lal·bun·sea·fl1·mls·ucl·uel·unl). 결과 마켓 거래량 합 ≥ 2만 달러(전략 `min_game_volume_usd` 와 같음),
  미국 종목 프리시즌 창(`risk/promotion.PRESEASON`) 제외. 품질 필터는 두지 않는다(엔진 재생과 같은 표본).
- 1분 격자: 예정 시작부터 min(시작 + 종목 최대 시간, 종료)까지 매 분, 값은 그 분 이전 최신 canonical 바(poll_mid > ws_last > history),
  120초 넘게 오래되면 결측. 체결 판정은 원래 바(분 정렬) 그대로.
- grid(종목마다 120칸): T 4개(60·70·80·90%) × Y 10개 × W 3개. δ = 0.03, c = 0.05, hs = 0.005 고정. 5 종목 합계 600칸.
- 분할: 종목별 표본 경기 시작 시각 중앙값으로 H1/H2(모든 칸 공통). 시즌: 축구·NBA·NHL·NFL 은 7월 기준, MLB 는 연도.
- 판정 규칙(maker 체결 기준, 하나라도 어기면 탈락; 최소 건수는 `risk/promotion.sample_rule` — 기본 n ≥ 40·반기 ≥ 10, NFL n ≥ 20·반기 ≥ 5):
  - R1 체결 n ≥ 최소, 전체·H1·H2 ROI ≥ 0, 각 반기 n ≥ 반기 최소
  - R2 이웃(T ±1, Y ±1, 같은 W, 최대 4칸) 중 체결 n ≥ 반기 최소인 칸의 절반 이상이 ROI ≥ 0, 이웃 포함 합산 ROI ≥ 0
  - R3 거래당 ROI 의 bootstrap 80% 양측 하한 > 0(저장소 승격 게이트와 같은 기준). 95% 단측 하한 > 0 이면 "유의(95%)"로 따로 표시
  - R4 각 반기 손익 ≥ +5 USDC(1단위)
  - R5 체결 20건 이상인 모든 시즌 ROI ≥ 0
  - R6 스트레스 두 가지 모두 ROI ≥ 0: (a) 스프레드 0.02(hs 0.01, 지정가가 한 칸 더 아래) (b) 엄격 관통 — 바가 L − hs 보다 낮아야
    체결(합성 매도호가가 지정가 아래, 대기열 맨 뒤 가정)
  - R7 엔진 재생: 구현한 `lts` 전략 코드를 `polylab backtest`(maker 바 관통 체결 모델, 현재 수수료 0.05 강제 — taker 체결에만 적용)로
    같은 사본에서 재생해 정규시즌 n ≥ 최소, ROI ≥ 0, 두 반기 ≥ 0
- 다중 비교 점검(H1 선택 → H2 평가): 종목마다 (1) H1 체결 ROI 상위 20칸(H1 n ≥ 반기 최소)의 H2 ROI 중앙값과 H2 ≥ 0 비율,
  (2) 아래 선택 규칙을 **H1 데이터만으로** 적용해 고른 칸의 H2 ROI. 둘 다 ≥ 0 이어야 그 종목의 양수를 강건하다고 본다.
- 선택 규칙(arm 마다, H1 만 사용): 후보 = 그 arm 의 T 층에서 H1 체결 n ≥ 반기 최소인 칸. 점수 = H1 의 이웃 포함 합산 ROI
  (자기 칸 + T ±1·Y ±1 이웃, 같은 W), 동률이면 H1 n 이 큰 칸. 고른 칸을 전체 표본으로 R1–R7 에 넣는다.
- **A/B 설계(사전 고정)**: arm A = `lts-king`(계좌 king) — T ∈ {80%, 90%} 층의 선택 칸(늦게·임계 낮아도 됨, 연구자 예 "80%·0.60"),
  arm B = `lts-queen`(계좌 queen) — T ∈ {60%, 70%} 층의 선택 칸(이르게, 연구자 예 "60%·0.61"). 같은 종목·같은 규칙에서
  진입 시점만 다른 두 arm 을 비교해 "늦을수록 안전한가"를 paper/실거래 표본으로 검증한다.
- live 판단(종목 × arm): R1–R7 + 다중 비교 점검 통과 **그리고** 경기 중 지정가(post-only GTC)가 실제로 걸려 있는지 확인됐을 때만
  5 USDC live. 나머지는 paper. 통과 칸이 없는 (종목, arm)도 선택 칸으로 paper 를 돌려 out-of-sample 표본을 쌓는다.
- 계좌 충돌 방지: king·queen 에는 plum-king/queen(paper)이 이미 있다. 한 계좌에 live 변형이 둘이면 `registry.load_all` 이 예외를
  내 tick 전체가 멈추므로, 승격 게이트·validator 가 "다른 live 변형이 이미 쓰는 계좌"의 paper→live 를 거부하도록 먼저 고친다.
